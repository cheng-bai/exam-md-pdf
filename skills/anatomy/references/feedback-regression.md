# 反馈与回归

用户指出作品或 Skill 问题时，先保留原始反馈与现有作品，不把推测当成已复现事实。按任务授权在本次任务工作目录或输出目录的 `feedback/` 下建立简短反馈记录；未获授权时不写入正式作品包。无反馈时不必创建空日志。

1. **记录与复现。** 记录日期、用户原话或来源、作品/Skill 路径与版本、相关场景和操作、预期与实际现象、截图或日志等证据，以及复现结果（已复现、未复现或受阻）。不记录不必要的个人信息；复现受阻时说明条件，不声称问题已修复。
2. **定位与处理。** 说明受影响的数学模型、交互、渲染、工具或说明，以及一次性需求还是可能反复出现的问题。在授权范围内先修复当前问题；需要时优先形成最小复现、回归测试或经认可的样例，再考虑修改工具和 Skill。长期规则须有适用范围和依据，并经用户认可；单次偏好只用于当前任务。
3. **回归与证据。** 写明修改对象、受影响检查、命令或操作、受检版本/文件哈希、结果及证据位置。内容改变后重跑相关检查，不沿用不匹配的证据。结构或哈希校验只证明其覆盖的内容，不能代替数学正确性、实际浏览器交互和公式视觉检查。
4. **确认与恢复。** 明确报告自动验证、AI 评估、人工确认、尚未验证四类状态及各自范围；未执行或未确认不得标为通过。数学与关键交互须有相应检查证据；桌面、手机显示和公式须实际检查，触摸未测须单列。教学价值与审美留待人工判断。保存修改前版本或可恢复依据；已封存作品创建新版本，不覆盖正式作品，不自行发布。邀请用户确认需要人工判断的结果，未确认时保持待确认。

## 最小记录模板

```text
日期／反馈来源：
作品或 Skill 路径、版本／场景／操作：
预期、实际、原始证据：
复现结果及条件：
影响范围／单次需求或长期候选：
修复与沉淀（案例、测试、工具或说明）／恢复依据：
回归命令或操作、受检版本或哈希、结果及证据：
自动验证／AI 评估／人工确认／尚未验证：
```

例如，构造一个“切换视角后读数改变”的案例时，固定参数与场景、记录操作和前后读数，并在修复后重跑对应状态测试；这只是示例，不表示该问题曾真实发生或已通过人工验收。
