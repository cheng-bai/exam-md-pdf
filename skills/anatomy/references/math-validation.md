# 数学交互验收

按实际功能选检查。不要固定运行与本任务无关的机械全套审计，也不要只用文件存在或截图代替正确性检查。

## 数学检查

1. 核对原题、定义域、约束和单位；给出关键公式的推导或可追溯依据。
2. 用独立关系验证核心算法。例如截面顶点同时落在原棱和截平面上，面积同时用三维多边形面积与独立解析式核对。
3. 覆盖典型值、端点、临界值、临界两侧、退化和空集。只覆盖可演示的定义域时明确范围；原题无界不因控件有界而得到全域结论。
4. 判断使用未舍入值与有解释的数值容差；解析可识别的临界值优先精确分类。检查 NaN、Infinity、除零和不合法输入的可见响应。
5. 独立复核数学与教学用途；报告是子 agent 复核还是第二遍自查。没有学生材料时只给潜在教学卡点，不捏造学生错误。

## 状态与交互检查

- 固定数学参数，旋转/缩放/平移：模型坐标、分类、读数保持一致。
- 固定数学参数与视角，切换讲解步骤/辅助线：模型和答案不变。
- 参数改变后，图形、公式、读数与分类同步；精确临界值可达，退化/空集不会显示上一帧的旧图。
- 预设→拖动/滑块→切步骤→重置串行操作正常；不存在控件值、模型值、显示值不一致。
- 覆盖实际存在的鼠标、键盘、触摸交互；触摸不可用时注明，不声称仅凭390 px截图验证了触摸。
- 若有播放，检查暂停、离屏暂停和 reduced motion；没有动画就不为了测试而新增动画。
- 若有多实例或卸载逻辑，再测状态隔离与事件/动画清理；单页单实例不强加组件工程。

## 渲染与视觉检查

- 从源内容独立计数公式，与实际渲染节点比较；无渲染错误、raw TeX残留和意外远程依赖。原生 MathML 检查渲染结果与浏览器支持，不只数标签。
- 逐场景检查题干、证明、图旁映射和动态读数中是否漏掉斜线分式或文本根号；改变参数和切换场景后再看一次。对照原式核对分子、分母、根号和符号，不把节点计数或无障碍文本当作视觉正确性的证明。
- 至少实际查看桌面与约390 px宽截图；根据图形再看临界、退化、遮挡明显或标签密集状态。记录已检状态，不把抽查描述成全状态审阅。
- 长公式在窄屏可完整阅读（必要时局部横向滚动），不裁切分数或撑坏页面；检查行内公式基线、行距与换行。既要检查独立 HTML，也要在最终交付容器或 iframe 的实际 CSP 下核验公式、脚本和字体；HTTP 成功不代表离线或嵌入成功。
- 平面等比例、三维投影、图例、坐标标签、颜色对比和文字溢出符合用途。必要时用截面正视图帮助学生区分屏幕投影与真实形状。
- 浏览器没有未处理异常。资源缺失、WebGL降级和字体加载问题真实报告。

可使用原有 `scripts/capture.mjs` 与 `scripts/drive.mjs`，也可使用当前项目已有 Playwright。先查看命令帮助，创建截图目录。仅在真正绘制了实体机械装置时额外运行其几何审计；数学虚线/向量/图表不运行机械线端“零悬空”门槛。

## 交付检查

离线目标要直接打开最终交付 HTML，阻止网络后再验证关键交互和数学渲染；HTTP预览通过不等于离线交付通过。源码可拆模块，独立HTML应把运行所需代码和资源带齐。不要将模型依赖写成某台机器的私有绝对路径。

简述：成品路径、使用方法、数学验证、交互实测、视觉抽查、未测范围。保留源码、推导或检查脚本及简短结果；修改参数/数学模型后重跑受影响检查。不上线、不外发、不修改其他项目，除非任务另有授权。


按[资源规范 v1](resource-package.md)交付时，另外验证清单与全部载荷哈希、固定版本冲突、场景深链接、移动后重新解析及 ZIP 导入回读；把实际受检文件哈希绑定到各类验证证据。清单和数据库校验通过只能证明归档一致性，不能替代上面的数学、交互和视觉检查。
