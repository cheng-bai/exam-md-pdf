# Anatomy · 数学可视化与交互

数学对象、条件和变化关系是主角。优先让读者看见“哪些量改变、哪些关系不变、为什么出现临界状态”。复用原有 SVG、投影、立体着色与交互工具；是否使用仪器或机械隐喻由教学目标决定。

制作数学作品时同时阅读[教学与阅读设计](references/math-teaching.md)，以可观察的数学发现、清晰的解释和克制的视觉组织为验收目标。

工作地图：题目与教学目标 → 选择数学或机械分支 → 模型与交互 → 数学、浏览器和视觉验收 → 作品包与按需归档。数学分支的模型、交互和渲染共同依赖同一数学状态；验证证据须对应实际受检版本。收到作品或技能反馈时，按[反馈与回归](references/feedback-regression.md)处理，不直接把单次要求变成长期规则。

## 先选择表达方式

| 当前目标 | 推荐表达 | 按需阅读 |
|---|---|---|
| 函数、平面解析几何、单位圆、数列、概率 | 等比例二维 SVG，图形与公式/表格联动 | [数学设计](references/math-design.md) |
| 空间位置、截面、投影、向量、旋转体 | 三维数学模型＋正交投影 SVG；需要时选择成熟 3D 渲染器 | [数学设计](references/math-design.md)、[kit API](references/kit.md) |
| 尺规构造、拉绳椭圆等机制本身有数学意义 | 适量仪器结构＋准确的数学对象 | 数学设计；确有实体装配时再读机械规范 |
| 明确要求精细机械技术插画 | 原版等轴测绘图流程 | [机械插画分支](references/mechanical-workflow.md) |

不要把所有数学对象做成机器，不设零件数下限，不为填满画面添加螺丝、管线或底座。二维内容不强制转成等轴测。普通函数图像不应承担机械装配审计。

## 数学制作流程

复杂任务先简述教学目标、交付物和验收范围；简单任务直接制作。先完成可操作的小样，再增加必要细节，按实际进展报告，不套用固定工时或强制等待用户选择规格。

1. **明确数学任务。** 从题目或上下文确定对象、定义域、参数范围、条件、单位、观察问题与需要解释的结论。给定原题时保留完整题干和来源；缺条件且影响结论时再问。
2. **先建纯数学模型。** 用独立模块计算点、曲线、截面、分类状态和读数。写明推导、可复算的不变量以及边界/退化情形。数值近似标注精度，不把采样结果当作全域证明。
3. **分开三类状态。** `mathState` 存数学参数；`viewState` 存视角、缩放、平移；`lessonState` 存步骤、提示和辅助对象显隐。视角与讲解操作不得暗改数学参数。图形、公式和判断读取同一模型结果。
4. **建立数学视觉语法。** 允许点名、坐标轴、刻度、向量箭头、角标、虚线辅助线、隐藏边、半透明平面与图内短标签。区分条件、主对象、辅助构造、轨迹；颜色加线型或文字，不能只靠颜色。平面欧氏几何默认 x/y 等比例；三维屏幕投影中的长度角度不能直接当真实量。
5. **让交互对应数学动作。** 参数滑块、受约束拖点、精准数值输入、典型状态预设、步骤切换、辅助线显隐和重置按需选择。每个控制要有教学作用。定义清楚拖拽约束，触摸/键盘可用；拖动图形与旋转视图分开。临界值能精确到达，非法/空集/退化状态有诚实展示。
6. **真实渲染公式。** 使用 LaTeX＋本地 KaTeX/MathJax，或浏览器可实际渲染的原生 MathML。禁止用 raw TeX、Unicode 上下标或截图代替可渲染公式；题干、证明及关键联动说明中的分数用上下分式，根式用真实根号，不只检查独立公式块。动态生成或更新的内容也须重新渲染；公式与图形同步，离线目标不依赖 CDN。需要渲染/导出细则时读取当前可用的数学渲染技能。
7. **教学优先的动效。** 默认静止、由用户控制；只有变化过程本身有解释价值才增加播放/暂停。数学参数可以连续变化，但边界分类必须按当前真实状态更新，不能为缓动而伪造答案。离屏暂停，遵守 reduced motion；不强制待机巡游。
8. **验证并交付。** 按[数学验收](references/math-validation.md)核对数学、交互、公式、视觉与交付。交付可运行 HTML/SVG 或用户要求的组件、模型源码和实际检查记录，并按下节形成标准作品包；说明定义域、近似、尚未测试范围。多份题目或答案材料按用户既有学生/教师版约定制作，普通概念演示不强制拆双版。
9. **归档交互作品（可选）。** 完成可运行数学交互作品后，如本机已安装并可用交互实验室归档技能，按该技能自主判断分类和标签；未安装时不要依赖私有路径，交付完整作品包并说明未归档。用户明确只要图或组件、不归档，或尚无可运行入口时遵从范围；归档受阻时说明原因，仍交付作品。

## 标准作品包与数据库索引

数学作品默认遵循[资源规范 v1](references/resource-package.md)。制作前读取该规范，新作品按 [manifest 1.1](schemas/manifest-v1.1.schema.json)准备元数据，保留读取 manifest 1.0 的兼容性；用户明确限定只要图或组件时按其范围交付，并注明未归档。

- 每件作品使用永久 UUID 与固定 `major.minor.patch` 版本；同一版本封存后不可覆盖。改名或移动保持 ID，独立改编生成新 ID 并记录来源。
- 交付包携带 `manifest.json`、入口、必要源码/依赖、许可和实际验证证据。使用相对路径和逐文件 SHA-256，包内不保存本机数据库路径。
- 场景使用稳定 ID 与独立的数学/视角/讲解初始状态，HTML 支持 `#scene=<id>`；实际测试深链接能恢复场景。
- 引用使用 `anatomy:<uuid>@<version>[#scene=<id>]` 文本标识，经索引解析为当前入口 URL；不要把文件名或绝对路径当永久身份。
- `scripts/resources.py` 提供封存、校验、SQLite 入库/检索、引用解析、关系查询、移动、ZIP 导出/导入与重建。清单是事实源，索引可重建；同 ID＋版本的内容冲突须停止，不能自动覆盖。
- 需要关联题目时读取[题目绑定规范](references/question-bindings.md)：使用命名空间＋稳定题目 ID＋可选小问，固定作品版本、场景及数学/视角/讲解初始状态。关联独立保存为不可变 JSON 记录并由 SQLite 索引；支持双向查询、解析、重建与随包传输。新作品声明状态契约并真实恢复参数；旧 1.0 仅绑定作品/场景。
- 优先使用用户指定资料库；未指定时将索引放在本次输出目录。不得据此扫描其他目录、上传、公开发布或修改外部讲义。
- mathematics、interaction、visual、offline 分别记录状态和受检文件哈希。结构校验不会替代数学与浏览器复核；改内容后不得沿用不匹配的通过证据。

## 数学验收的关键边界

- 独立复核数学推导、条件、单位与实际教学用途；可用且获准时由独立子 agent 复核，否则第二遍自查并说明范围。
- 覆盖典型状态、临界值、两侧邻域、退化/空集及允许的非法输入；核验脚本不得只复述渲染实现。修改参数范围、初值或数学模型后，重跑受影响检查。
- 实测“改视角不改答案、改步骤不改参数、重置能恢复初始状态”。比例、坐标映射、拖点约束和求交结果需要可复算证据。
- 公式节点真实存在且无渲染错误；查看桌面与约 390 px 手机截图，以及能暴露遮挡/标签碰撞的关键状态。截图必须实际读过。
- 原有 `kit/audit.mjs` 只用于适用的实体装配与遮挡问题；`scripts/lines.mjs` 只用于适用的机械装饰线。数学曲线、坐标轴、箭头、虚线与有意交点不要求落在机械表面，不为通过审计而改变数学。
- 审计通过不代表数学证明、CAD 精度或可打印性；若需要 STEP/STL 与工程测量，使用 Text-to-CAD 等 CAD 工作流。

## 工具与可运行数学小样

无需安装新的绘图框架才能使用数学分支。已有项目/成熟数学场景组件适配时优先复用；不为一个示意图搬入整套系统。模型与浏览器展示使用一致的数学代码，检查另用独立关系验证。

- [`examples/math-tetrahedron/`](examples/math-tetrahedron/CONCEPT.md)：正四面体的平行截面，独立模型、可调截面高度、视角、讲解步骤、正交投影和等比例截面图；原生 MathML，无远程资源。先运行 `node examples/math-tetrahedron/check.mjs`，再运行 `node examples/math-tetrahedron/build.mjs --out <输出目录>`。`package.mjs --out <空目录>` 可生成可移植作品包草稿，数学检查真实运行，其他验收保持 pending；按资源规范完成检查后封存。这是数学分支的起点，不代表所有数学题都适合截面演示。
- `kit/iso-kit.mjs` / `.ts`：`iso`、`fitProjection`、`pathOf`、几何绘制与卡片；[`scripts/inline-kit.mjs`](scripts/inline-kit.mjs) 可内联核心实现到离线 HTML。
- `kit/react/draw.tsx` 与 `live.tsx`：已有 React 项目中的图形与交互。按需读 [React 适配](references/react.md)，每个实例隔离状态并清理事件/动画。
- `scripts/capture.mjs`、`scripts/drive.mjs`：截图、关键状态与无 WebGL 降级。也可复用当前项目的浏览器测试工具。
- `kit/lathe.mjs`、`tube.mjs`、`audit.mjs`：仅在需要真实仪器、曲面实体、管线与实体审计时使用。
- WebGL/着色器或原版 3D 模式是选项，选择后读取 [WebGL](references/webgl.md) 或 [3D](references/3d.md)。数学空间交互不强制使用仍处于 beta 的机械 3D 运行时。
