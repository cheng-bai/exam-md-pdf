# HTML 数学讲义出版

保留内容底稿，用可验证的 HTML 出版流程交付讲义，而不是用缩字、截图或隐藏内容凑页数。HTML 是页面技术；公式仍保留标准 LaTeX 源码。用户已指定路线时不切回整页 LaTeX，也不把本案例的紧凑参数强加给所有文档。

## 入口与资源

- 先复用项目已验证的字体、KaTeX/MathJax、Chrome、导出脚本和 Node 依赖。不要把 node_modules、浏览器或整份私有讲义放进 skill。
- 运行与故障细节：[`references/build-and-check.md`](references/build-and-check.md)。缺资源、目录/书签异常、不等号或编号异常时按需读取。
- 需要了解参数和证据范围时读 [`references/verified-case.md`](references/verified-case.md)，不要将案例页数当作新材料验收标准。
- 新的出版配置可使用 `scripts/prepare_publication.py` 与 `assets/paged.css` / `assets/compact.css`；它们是覆盖样式，不替代原文的图文样式。
- `scripts/audit_publication.py` 做结构和内容保真检查，可生成预览；它不代替看图、点击导航或数学复核。

## 工作流程

### 1. 冻结内容和比较条件

记录来源、文件哈希、正文范围、题目顺序、公式数、图片与来源说明。只排版时不改写证明或重新分类。保留已交付版；新输出用有意义的中文文件名。

样式迭代从同一份已经渲染的基线出发，先核对正文与公式，再比较版式。若用户要学生版，先按既有授权另做答案隔离，不能把教师版简单改标签交付。

### 2. 选择导出器

- 短讲义或快速打印：优先已有 Chrome 打印脚本。
- 多章节、自动目录、层级书签、章节页眉：选择已验证的 Vivliostyle。
- 不因“新技术”重复安装依赖；记录实际版本，不声称安装的是全网最新版。
- 没有计时对照就不说更快；页数减少也不是引擎质量或效率的独立证明。

### 3. 先完成公式，再分页

保留 `data-tex` 或同等源码底稿。浏览器路径等待字体和公式就绪；Vivliostyle 优先静态预渲染，避免把执行时机交给出版引擎猜测。检查输入公式数、输出数和错误节点，不把 OCR 源文本直接当公式。

`prepare_publication.py` 只接收已渲染 HTML，拒绝未渲染的 `.math`；先使用项目已有渲染脚本。不要无条件使用示例中的不等号补丁，或用正则盲改含嵌套括号的公式编号。

### 4. 建立分页单元

题干、解析、教学提示和来源共同组成 `.problem-unit`，不只包题干卡片。图形与图注尽量同页。

用户要求题干统一底色或边框时，另建 `.question-head` 包住题首、所有小问、表格与原题图，样式作用于整个容器而非首个段落；在答案、考点或解析开始处结束。按语义识别边界，不把“（1）”一律判为解答。结构检查后查看实际 PDF 的框底、跨页和末行；保持正文、公式及原图对账，获准新增的解析图单独登记。

大题题头只保留序号，不把分值分配写进题头（用户明确要求保留时除外）；大题考点按小问逐项对应，不用一条笼统描述替代。

答案摘要用左对齐的普通行内排版；各小问答案连同标点作为不可拆分的短段，不用两端对齐、`space-between` 或固定宽度分栏，避免标点孤行。用浏览器打印 KaTeX 时，导出前删除仅供无障碍读取的 `.katex-mathml` 节点，只保留可见公式；否则 PDF 文本层会把同一公式输出两遍。删除后仍核对公式视觉与可复制文本。

```html
<section class="problem-unit">
  <!-- 题干、完整解析、提示、来源；原有顺序不变 -->
</section>
```

在实际打印宽度、字体和公式完成后测量单元高度，与扣除页边距后的可用高度比较：能放下一页的尽量整体移动；超高单元标记 `.allow-split`，按步骤续排。测量只是预判，最终检查 PDF 起止页。单个步骤也超高时必须允许它自然续页。

把“方法说明＋关键推导＋最终结论”组合为较小的 `.keep-step`，避免翻页才看到结果；不要将全部解析串成不可分页大盒。所有新增包装应保持规范化正文、公式顺序和图片内容一致。

### 5. 迭代密度与出版结构

- 按顺序收紧：装饰和卡片内边距 → 段落/标题/公式间距 → 页边距 → 行距；最后才考虑字号。教师紧凑版可从正文 10.5pt、行距 1.38 起步，不是硬性统一标准。
- 不把整页留白都当成错误：完整短题整体换页可能需要留白；过大的留白再查是否存在过长的 keep 链。
- 各级标题使用唯一稳定 ID；印刷目录页码、目录链接和 PDF 书签分别核验。
- Vivliostyle 构建入口优先 ASCII 名，中文保留给用户可见 HTML/PDF。构建输出有书签不代表目标页正确。
- 普通/紧凑对比保留同样正文、公式与可读字号；不要强制各版相同页数。

### 6. 验收与修复

1. 机器检查：A4、页数、作者元数据、HTML 正文和公式/图片保真、渲染错误、资源存在、明显 TeX 残留。HTML 对账不证明 PDF 全文未丢失；另核对 PDF 正文的题序、关键起止内容及可比较字符，结合视觉检查。
2. 导航检查：从实际标题页建立期望表，核对印刷目录、点击链接和书签目的页，不用生成器自己的目录作唯一真值。
3. 版面检查：查看最终 PDF 每页或明确记录抽查页；检查箭头、根号、分数线、不等号、编号、图注、窄行和跨页结论。生成 PNG 不等于已经查看。
4. 记录每题完整题块的起止页；短题同页与超长题合理跨页分别验收。
5. 修复后重跑受影响检查；复杂材料有条件时独立复核。排版验收不冒充数学审校。

### 7. 交付和清理

交付可点击 PDF、可编辑/离线 HTML、必要资源和简短验证说明。默认作者 `chengbai` 仅写入元数据，不新增可见署名；用户要求优先。

不要复制 PDF 提取出来的公式当编辑源；回到 HTML / 数学底稿。不要未经授权外发、上传或改写全局偏好。

用户要求总结/清理时，仅处理本次可再生缓存和重复中间件；保留成品、内容源、必要预览/报告与依赖。可逆压缩归档后移除原缓存，校验清单与恢复方法；移动到废纸篓不计作释放空间。无对话开始基线时明确新增量未知，不能用目录总量替代增量。

## 边界

只排版不改题意；不自动补解、审校或分发私有材料。不承诺任意长题单页，也不将自动检查包装成视觉/数学审校。已有工作路径与用户明确授权优先于案例模板。

## 质量标准

报告实际采用的导出器和版本、内容是否变化、页数/分页结果、已查看页范围、导航核验、交付路径、限制及清理账目。结构检查、视觉复核、数学审校、速度对比是不同证据，不合并宣称。
