# 试卷电子化标准流程

## 1. 接收与分类

- PDF、照片和扫描图放入 `inputs/`，默认不提交。
- DOCX 先确认文件有效，再转换成 Markdown 初稿。
- 判断目标是单份试卷、专题讲义还是大型汇编，分别进入 `exams/`、`handouts/` 或 `collections/`。

## 2. 建立工作稿

```bash
python3 scripts/check_environment.py
python3 scripts/new_exam.py "年份学校标准名考试名称"
```

工作稿和 OCR 中间物保留在本地工作目录，不直接作为云端成品。

## 3. 解析与逐题审校

- 纯文字扫描优先使用 PaddleOCR 获得行级初稿。
- 复杂公式、表格或版面可考虑 MinerU，但必须先确认适配脚本可用；当前默认适配缺失时不得把它作为稳定入口。
- OCR 只作为初稿；题号、公式、分值、选项、图形必须对照原卷校验。
- 不确定内容明确标记，不能静默猜测。

## 4. 形成 Markdown 主源

- 数学公式使用标准 Markdown LaTeX。
- 图片使用仓库相对路径，必要题图放入最终目录的 `figures/`。
- 学生版不泄露答案；解析版把答案和解析放在对应题目附近。
- 最终文件使用项目规定的中文语义名称。

## 5. 渲染和验证

```bash
python3 scripts/render_exam.py "exams/<归档目录>/<中文语义文件名>.md" --min-pages 1
```

- PDF 必须可打开、页数合理且为 A4。
- 检查第一页、最后一页、公式密集页和图片密集页。
- 修订后重新渲染，不能把旧 PDF 当作最新证据。

## 6. 归档与发布

- 单份试卷采用“一份试卷一个文件夹”。
- 同名 `.md/.pdf` 必须同时存在。
- 运行 `workflows/公开发布检查清单.md` 中的检查。
- 用户确认公开授权后，才允许推送到公开仓库。
